# Deploying EthioTriLingo (Vercel frontend + Render backend + Neon database)

```
Browser ──> Vercel (Angular)  ──/api/*──>  Render (Express)  ──>  Neon Postgres
```

Vercel serves the Angular app and forwards every `/api/*` request to Render
(see `vercel.json`), so the browser only ever talks to one domain and there are no CORS problems.

## 1. Backend on Render
1. Push this repo to GitHub.
2. Render → **New → Blueprint** → pick the repo (it reads `render.yaml`).
   (Or **New → Web Service**: Root Directory `server`, Build `npm install`, Start `npm start`.)
3. Set environment variables:
   - `DATABASE_URL` – your Neon connection string
   - `CORS_ORIGIN` – your Vercel URL, e.g. `https://ethiotriolingo.vercel.app`
   - `JWT_SECRET` – auto-generated by the blueprint (or set a long random string)
4. After deploy, open `https://<your-service>.onrender.com/api/health` – you should see `{"ok":true,...}`.

## 2. Frontend on Vercel
1. In `vercel.json`, replace `https://ethiolingo-api.onrender.com` with **your** Render URL.
2. Vercel → **Add New Project** → import the repo. Leave the Root Directory as `.`
   (build command and output directory come from `vercel.json`).
3. Deploy, then test Sign Up.

## Notes
- Render's free plan sleeps after ~15 min idle; the first request can take 30–60 s.
  The app now shows "server is waking up, try again" instead of a broken message.
  Use a paid plan or a free uptime pinger on `/api/health` to avoid this.
- **Rotate your Neon password** (Neon dashboard → Roles) if `server/.env` was ever shared or committed.
- Local dev is unchanged: `cd server && npm start`, then `npm start` in the root.
